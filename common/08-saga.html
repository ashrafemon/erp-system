08 · Saga — Company-Configurable Orchestration

Role: long-running cross-aggregate processes on ERP-standard defaults that every company narrows at runtime with its own overlay. Defaults are found by event name + version; overlays only narrow, never widen.

Contents · Ports · Tables · Definitions · Format · Flow · Sequence · Patterns · Examples · Layout · When not · Config · Rules

Public ports

The saga owns no billing, plans or subscriptions — only feature keys + settings + company overlays. Business modules expose actions; the saga calls them, never repositories.

methods
FeatureGate.enabled(companyId) → ReadonlySetOpaque capability keys (procurement, valuation, finance …) — owned outside the saga.
CompanySettingsReader.get(companyId) → settingsgrnSources, costingMethod, accrual flags — read at plan build, snapshotted.
SagaAction.do(ctx) → ok | retry | failOne command on one aggregate via its application service; ctx carries companyId, instanceId, stepId, idempotencyKey (= step row id), saga, input.
SagaAction.undo(ctx + doOutput) → ok | retry | failBusiness reversal (reversal document, never delete); idempotent, retried until ok.
SAGA_ACTION multi-provider tokenEach module registers its own actions; SagaModule imports nothing from business modules.
PlanBuilder.build(def, cfg, ctx) → plan | nullMerges default + overlay (if/when AND-combined, timeout/retry overridden); empty or unentitled → null, no instance.

Table definitions

table → purpose
Saga DefinitionsPlatform-owned defaults, found by (event_name, event_version) index. Never per-company.
Saga Company ConfigsOne ACTIVE overlay per company+saga: enabled flag, conditions, timing. No row means the default applies.
Saga InstancesOne live row per correlation key with its merged plan snapshot, cursor and reason.
Saga StepsDurable work queue (claim + lease), execution log and audit trail in one table.
Saga InboxDedupe by (company, consumer, event) plus buffering, version-aware ignores and reasons.

Definition format

Linear steps, three small expressions, safe evaluator (JEXL/CEL — never eval). Variables: event, saga, company.settings, steps.<id>.status/output. Templates use {{ }}.

field → meaning
saga: key, version, requiresidentity + feature keys the saga needs to exist
start: event{name, version}, when?, key, contexttrigger event by name+version, optional filter, correlation-key template, values copied into the saga
cancelOn[]events {name, version} that cancel a live instance and compensate, matched per key
step: id, policyrequired (cannot be switched off) / standard (on, can be switched off) / optional (off, can be switched on)
step: do, undo, input?action names + optional input from earlier outputs; every do needs undo or pivot
step: waitFor{name, version}, match, when?versioned event, key template equal to the instance key, per-event filter
step: requires, if?feature keys (bypass if missing), condition when reached (bypass if false)
step: timeout, onTimeoutwaits only: skip or compensate
step: retry, pivotmax attempts for technical failures; pivot = point of no return
overlay: enabled, start.whencompany runs this saga; extra start-event filter (AND-combined)
overlay step: enabled, if, when, timeout, retryswitch optional on, narrow with extra conditions, own timing — never do/undo/requires, never required-off, never new steps
onComplete.emitsaga lifecycle event on finish

Company props for conditionals. Start context merges three sources, frozen at start: event facts win, then company settings, then overlay literals. Conditions read the merged props, e.g. an overlay adds region: 'EU' and a step gates on saga.region == 'EU'.

Event identity. Additive field = same version; rename/remove/remap = new version with dual-emit migration; router matches name+version exactly; unknown version alerts, never silently drops.

Flow — publish, route, run

sequence
1Publish: platform BASE definition (ERP-standard steps). Company overlay saved separately (enabled/when/timeout/retry/if only); unknown step, required-off, bad expression or failed checks reject the save. New default version re-validates every overlay — failures become INVALID (default applies) + alert.
2Router per event: ACTIVE defaults by (event_name, event_version) index + company overlay + features/settings → buildPlan per instance. Nothing is precompiled per company.
35 checks in order: requires+policy (exists for this company?) → overlay (allowed?) → if (relevant now?) → when (this event?) → match (this correlation key?). Bypass means continue, never wait — a saga never waits for an event the company cannot produce.
4Start: overlay enabled? start.when passes (default AND overlay)? → inbox tryInsert UNIQUE(company, consumer, event) — duplicate skipped → instance + definition_id + config_id + plan snapshot + cursor 0 under one live correlation key. Empty plan → nothing starts.
5Advance: if false → SKIPPED; do → build input (incl. company props) → PENDING row, stop for the worker; wait → consume oldest BUFFERED match or create WAIT row (run_at = timeout), status WAITING, stop.
6Worker claims PENDING rows (SKIP LOCKED + 60s lease, small batch, per-company fairness cap) → runs the action with idempotencyKey = step row id → ok stores output, retry backs off, fail compensates.
7Wait expiry, exhausted retries, business fail or cancelOn event → COMPENSATING with reason → UNDO rows in reverse completion order (worker retries until ok) → COMPENSATED + saga event, or FAILED_MANUAL + alert. Running actions are never killed (cancel_requested_at waits).
8Early events BUFFER by match and are consumed when their step arrives; causationId ignores the saga's own output (loop guard); onComplete.emit rides the shared outbox with saga headers.
9Changes (features, settings, overlay, new default) affect new instances only — running ones finish on their snapshot; revoked features keep actions callable so undo works; CONFIG_INVALID blocks starts + alert. Retention: partition steps by month, archive finished, purge inbox after the redelivery window.

Company runs valuate, post_stock, accrue. The accrual fails on a business rule (no GL mapping) — no retries, straight to compensation in reverse.

Config — robustness + efficiency

engine
WORKER_LEASE_S + CLAIM_BATCH60s lease, SKIP LOCKED small batch — workers never block each other
WAIT_AS_ROWStimeouts are PENDING rows (run_at = instant) — no separate scheduler
OVERLAY_IMMUTABLE + REVALIDATE_ON_PUBLISHchanges are new rows; failures become INVALID (default applies) + alert
RUNTIME_CACHEper-company features/settings/overlay + global (name, version) index; rebuilt on change, routing is a map lookup
FAIRNESS_CAPmax rows claimed per company per batch — no starvation
RETENTIONpartition saga_steps by month; archive finished instances; purge inbox after the redelivery window (days, batched)
OUTBOX_RELAYbatches ordered by created_at, partition_key for per-aggregate order

Rules

rules
Aggregates never know about sagasThey emit domain facts (grn.created, bill.posted) into the outbox; one step = one command on one aggregate via its application service.
Instances are keyed, not rootedCorrelation key only (GRN:grn_77) — no aggregate-root binding; one live instance per (company, saga, key).
Saga holds process state, aggregate holds business stateNever copy Posted into the saga; compensation calls a domain method; undo creates reversal records, never deletes.
Overlay only narrowsDefault AND overlay conditions; unknown step, required-off or bad expression rejects the save; no row means the default applies.
Company props for conditionalsStart context merges event facts first, then settings, then overlay literals — frozen at start; conditions read the merged props.
Event name + version exact matchAdditive field = same version; rename/remove = new version + dual-emit migration; unknown version alerts, never silently drops.
Business fail vs technical retryfail reason → compensate at once; retry → backoff to max_attempts; exhausted undo → FAILED_MANUAL + alert.
Pivot = point of no returnAfter a pivot step the saga only moves forward.
Empty plan means no instanceNo features, saga disabled, or every step bypassed → router stops; the event still exists for plain handlers.
Snapshots are immutableRunning instances finish on their plan + definition_id + config_id; revoked features keep actions callable so undo works.
Company in every keyInstances, steps, inbox rows, cache entries, queue claims — every query filters by company_id.
Idempotency first, inbox secondMake handlers idempotent; add inbox rows only when they cannot be; insert inbox in the same tx as the work.
Loop guardIgnore events whose causationId is the saga's own step output.
Closed periods + alertsReversals post in the open period; alert on FAILED_MANUAL, CONFIG_INVALID, overdue WAITING, growing PENDING.
No business importsPlatform never imports business modules; actions arrive via SAGA_ACTION providers.
