08 · Saga — Minimal Durable Orchestrator

Role: coordinate long-running cross-module processes (order, reserve, invoice, pay). Orchestrator only — every step executes a business use case that owns its rules, transaction, and outbox writes.

Contents · Ports · Table · Flow · Sequence · Layout · When not · Config · Rules

Public ports

Two sides. Process code calls SagaPort. Step owners implement SagaStepHandler and self-register at boot.

methods
SagaPort.start({...}) → { sagaId }Creates the instance. Idempotent on correlationId, safe to call twice.
SagaPort.handleEvent({...}) → voidAdvances one step. Duplicate events are ignored by claim.
SagaStepHandler.handle(stepCommand) → voidYou implement this. Call your own transactional use case inside.
SagaStepHandlerRegistry.register(this) in onApplicationBootstrapThe adapter registers itself. Duplicates throw at boot.
@Injectable()
export class ReserveInventoryStep implements SagaStepHandler, OnApplicationBootstrap {
  constructor(private readonly stepRegistry: SagaStepHandlerRegistry, private readonly inventoryUseCases: InventoryUseCases) {}
  onApplicationBootstrap() { this.stepRegistry.register(this); }
  async handle(stepCommand) {
    await this.inventoryUseCases.reserve(stepCommand.payload);
  }
}

Flow

sequence
1Start event arrives through Inbox.receive, SagaPort.start creates a RUNNING instance (idempotent on correlationId), then the step-1 handler runs in CLS (Continuation-Local Storage) context
2The step handler calls its business use case (own @Transactional plus idempotency key sagaId:step:attempt plus Outbox), then the step turns COMPLETED
3Next event, Inbox.receive, SagaPort.handleEvent (CAS (Compare-And-Swap) claim), duplicate? ignore, next step …, all done, COMPLETED
4Failure: bounded retries (base*2^n, max 5), step FAILED, run compensates steps in reverse (normal handlers issuing cancel/release), instance FAILED (with compensation record, not a separate COMPENSATED state)
5Sweep (@Cron 60s): PENDING/FAILED steps past nextAttemptAt, retry; stuck RUNNING past timeout, FAILED + alert. The same sweep deletes terminal instances past retention.

Config

env
SAGA_STEP_TIMEOUT_MS300000 — a WAITING step past this is retried or failed by the sweep
SAGA_MAX_ATTEMPTS5 — bounded retries with exponential backoff, then FAILED
SAGA_SWEEP_INTERVAL_MS60000 — converges stuck instances and expired step claims
SAGA_COMPLETED_RETENTION_MS7776000000 — COMPLETED and FAILED instances older than 90 days are deleted with their steps; RUNNING ones never touched

Rules

rules
Tenant splitEvery instance and step carries tenant plus organization. correlationId makes start idempotent.
Steps own nothingEach step calls a business use case holding its own transaction, idempotency key (sagaId:step:attempt), and outbox writes.
Bounded retries, real compensationCompensation is a new business operation (cancel, release), never a rollback.
Sweep converges straysStuck RUNNING work becomes FAILED plus alert for operators.
No business importsThe platform never imports business modules. Handlers inject the ports they need.
