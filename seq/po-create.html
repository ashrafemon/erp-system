Purchase Order — Create

Role: Create with cross-module reads: orderable vendor plus purchasable product through public-port contracts, numbering for the order number, merged lines.

Contents · Flow · Sequence · Sequence — async

Flow

steps in order
1Client posts CreatePurchaseOrderDto; controller calls CreatePurchaseOrderUseCase in one transaction.
2Use case reads company config for currency and approval threshold.
3OrderableVendorPort fetches the vendor reference through VendorForPurchaseFacade; non-orderable vendors fail with 409.
4PurchasableProductPort fetches each product reference; non-purchasable lines fail with 409.
5NumberingPort issues the next order number.
6PurchaseOrderFactory.create enforces invariants and policies; the aggregate instantiates and merges same-product lines, raising PurchaseOrderCreated.
7Duplicate order-number pre-check returns 409 when taken; command repository saves through the mapper on TransactionHost.
8Aggregate pullEvents drains into the integration port; OutboxAdapter appends through OutboxWriterPort in the same transaction.
9COMMIT persists state plus event atomically; controller answers with the new id.
10Async: scheduler claims the batch with the lease clause.
11MessageQueuePort publishes per broker while the bus re-emits in process; success marks PUBLISHED, errors back off, poison parks DEAD_LETTER.
