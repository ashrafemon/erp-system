09 · Context — Request Identity + Tenancy

Role: tenancy trust boundary. Removes per-request param threading; every layer reads tenant/org/actor from CLS. Queries use the replica via PrismaReadPort.

Contents · Ports · Flow · Sequence · Layout · Config · Rules

Public ports

Inject RequestContextPort anywhere. PrismaReadPort is the replica reader. TenancyAuthGuard is the APP_GUARD.

methods
RequestContextPort.get() / require() / getTenantId()Read current CLS ids — no param threading.
RequestContextPort.run(patch, fn)Only sanctioned child context — BullMQ workers, outbox re-dispatch, scheduler/recurring/batch/import.
PrismaReadPort extends PrismaClientReplica pool; falls back to write pool. Query repos inject this.
TenancyAuthGuard + @SkipTenancy()single trusts x-tenant-id; multi requires Bearer JWT (JWT_ACCESS_SECRET), tenantId claim else 401/403.
// background worker entry
await this.requestContext.run({ tenantId, organizationId, correlationId }, () => this.useCase.execute(input));

Flow

sequence
1HTTP: RequestIdInterceptor creates one CLS context (requestId, x-correlation-id).
2TenancyAuthGuard: single = pass-through headers; multi = verify JWT, stash VerifiedIdentity. Missing/invalid → 401, missing tenantId claim → 403.
3Any layer: requestContext.get()/require()/getTenantId() — never set() on request path.
4Background: run(patch, fn) restores tenant/org/correlation; require() throws if forgotten.
5Queries: *QueryRepository injects PrismaReadPort (replica).
