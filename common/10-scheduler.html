10 · Scheduler — Durable TIME Wake-Ups

Role: DB owns when, callers own what. schedule() writes a scheduled_jobs row; ticker claims (SKIP LOCKED) + Redis lock + BullMQ; registry handler or external topic.

Contents · Ports · Table · Flow · Sequence · Layout · Config · Rules

Public port

Business code touches only SchedulerPort. Handlers implement ScheduledJobFireHandler and register by jobType.

Flow

sequence
1Register: RegisterScheduledJobUseCase → PENDING row (one tx with caller).
2Poll: SchedulerTicker every 30s → DispatchDueJobsUseCase claimDue FOR UPDATE SKIP LOCKED → CLAIMED.
3Lease: DistributedLockPort.acquire({scope:'scheduled-job',resource:jobId}) — BUSY leaves CLAIMED for reconcile.
4Enqueue: BullMQ scheduler.jobs, jobId=idempotencyKey=sha256(jobId:slot); CRON → markPendingWithNextRun, EXTERNAL → stays CLAIMED until owner reschedule.
5Execute: bullmq-scheduler-job.worker → ScheduledJobProcessor: CANCELLED/SUSPENDED drop; registry hit → handle(payload) else publishJobDue.
6Failure: recordFailure backoff nextRunAt, retryCount++; maxRetries → SUSPENDED + DEAD_LETTERED. ReconcileMissedJobsUseCase releases stale CLAIMED/RUNNING.
