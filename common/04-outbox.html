04 · Outbox — Transactional Event Publication

Role: durable boundary between business transactions and async delivery. Business writes event + state in one DB transaction; scheduler publishes later. At-least-once.

Contents · Ports · Table · Flow · Sequence · Layout · Config · Rules

Public port

Inject OutboxWriterPort to announce an event. One call inside your @Transactional method, next to the save. The scheduler publishes later.

methods
append(event, aggregateType, aggregateId, opts?) → voidStored in the same DB transaction. Nothing leaves the process here. opts.broker defaults to rabbitmq.
@Transactional()
async execute(command) {
  const order = await this.buildOrder(command);
  await this.orderRepository.save(order);
  await this.outbox.append(new OrderCreated(order), 'SalesOrder', order.id);
}

Flow

sequence
1Business use case inside @Transactional: orderRepository.save plus outbox.append, then COMMIT atomically
2OutboxScheduler (OUTBOX_POLL_INTERVAL_MS, default 10s)
3claimBatch: UPDATE … WHERE id IN (SELECT … FOR UPDATE SKIP LOCKED) LIMIT batchSize
4status=PENDING AND nextRetryAt <= now AND (claimedAt IS NULL OR claimedAt older than OUTBOX_CLAIM_LEASE_MS), stamp claimToken/claimedAt, attempts+1 (no state change)
5MessageQueuePort.publish(envelope with broker param, default rabbitmq) plus InProcessEventBus.emit(envelope)
6success: PUBLISHED
7error: keep PENDING + nextRetryAt=backoff
8attempts>max: DEAD_LETTER, parked forever for operators (never auto-deleted)
9No reconciler: crashed owners surface as expired claimedAt and the next tick reclaims them through the same clause. Cleanup (1/h): delete PUBLISHED older than X
