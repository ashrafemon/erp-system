Authorization Service — Decisions, Grants, Delegation

Role: standalone decision service for the ERP. Consumes the entitled context (membership, company, center) from Auth and answers what a request may do. Owns roles, groups, permissions, company scopes, assignments, conditional policies, delegations, and SoD (Segregation of Duties). Default DENY (deny by default); explicit DENY always wins.

Contents · Ports · Tables · Columns · Enums · Flow · Sequence · Examples · APIs · Cache · Events · Config · Rules · Layout

Public ports

Guards and ERP modules inject AuthorizationPort. Callers pass the entitled context plus what is wanted; the service returns ALLOW plus a company scope filter plus obligations, or DENY.

methods
check({ principal, tenant, company, center, resource, action }) → ALLOW + scopeFilter + obligations | DENYFull pipeline: expand roles, match permission, attach company scope, evaluate policies, SoD (Segregation of Duties) screen.
sodCheck({ principal, role, scope }) → clean | conflictingPre-commit dry run for grants plus compliance reports over existing assignments.
approveAssignment({ assignment, approver }) → approved | rejectedMaker-checker: granter never approves privileged roles.
const decision = await this.authorization.check({
  principal: membershipId, tenant: tenantId, company: companyId, center: 'ERP',
  resource: 'purchase-order', action: 'approve'
});
if (decision.status !== 'ALLOW') throw new ForbiddenException();
return this.purchaseOrders.approve(id, decision.scopeFilter);

Flow — decision pipeline

steps in order, default DENY (deny by default)
1Expand roles — Direct assignments plus group roles through the membership, each inside validity window and maker-checker approved, plus every ancestor reached by walking parent_id chains transitively.
2Match permission — Find module, resource, action across the expanded set and collect effects.
3DENY wins — Any explicit DENY ends the pipeline denied; no match also means DENY (deny by default).
4Attach company scope — Bind the assignment company filter plus the own-row rule; nothing outside the company passes.
5Evaluate policies — Conditional policies for controlled operations only, by priority; DENY (deny by default) overrides.
6SoD screen — Dry-run conflicting role sets on every grant over the effective set (direct plus group-granted plus inherited); block or flag per rule.
7Answer — Return ALLOW plus scope filter plus obligations, or DENY. Role, ancestor-role, and policy changes bump versions to invalidate caches.

Examples — inheritance plus groups

One showroom, Company A. Three roles in a chain, one team group, two members. Follow Rahim from login to an allowed sale and one blocked grant.

role chain (parent_id links)
sales_clerk (no parent)inventory.product.read, sales.order.create
senior_clerk (parent: sales_clerk)inherits both above, plus sales.order.discount
sales_manager (parent: senior_clerk)inherits all three above, plus sales.order.approve
group (people batching)
Branch A Salesmembers M-101 Rahim, M-102 Sadia
group grantsenior_clerk to the group: one row covers both members
direct grantsales_manager to M-101 Rahim only, in Company A, ERP center
effective decision for Rahim approving order O-77
Expand direct:sales_manager, validity and approval pass.
Expand group:senior_clerk arrives through Branch A Sales.
Walk ancestors:senior_clerk pulls sales_clerk; sales_manager pulls both. Effective set: sales_clerk, senior_clerk, sales_manager.
Match:sales.order.approve found via the direct grant. No DENY anywhere in the chain.
Answer:ALLOW plus Company A scope filter. Sadia, holding only the group grant, would DENY on approve.
sod block on the same setup
Rule:sod_no_self_pay: sales.order.approve conflicts with sales.payment.release.
Attempt:grant payment_releaser to Rahim while he holds sales_manager through the chain.
Dry-run:conflict found in the effective set, not just direct grants. Grant blocked with 409 plus audit.

Cache keys

Decision caches hold ids and hashes, never materialized permission lists in tokens. Every grant-side mutation emits outbox, then deletes.

keys
authz:roles:{principal}:{tenant}:{company}:{center}expanded role+permission ids + version. TTL short (e.g. 60-300s). Invalidated by Role/grant/revoke/policy/scope/group/delegation change. hot path; key includes company+center (CHANGED)
authz:decision:{hash}ALLOW/DENY + scope filter hash. TTL very short (e.g. 10-60s). Invalidated by any relevant access change. hash(principal,tenant,company,center,resource,action,scope,policyV)
policy:{tenant}:{company}:{center}:versioncompiled policy set version pointer. TTL immutable per version; cache 1h. Invalidated by new version write (old ages out). NEVER materialized perms in token; pointer only

Events

State change and outbox INSERT share one transaction. Same-transaction rule and inbox dedup apply as in Auth.

events
8.0 RoleCreated/UpdatedTrigger: roles change. Effect: invalidate authz:roles:* + bump policy version. Via outbox
9.0 PermissionGranted/RevokedTrigger: role_permissions change. Effect: invalidate role/decision keys. Via outbox
10.0 RoleAssigned/RevokedTrigger: role_assignments change. Effect: invalidate affected principal keys. Via outbox
11.0 PolicyChangedTrigger: policies version write. Effect: invalidate policy:* + decision keys. Via outbox
12.0 DelegationStarted/EndedTrigger: delegations window. Effect: invalidate delegatee keys. Via outbox (+expiry sweeper)
13.0 SodViolationBlockedTrigger: grant conflicts. Effect: audit; block write. Via outbox (no state change except audit)

Rules — ERP authorization standard

rules
Default DENY (deny by default).Explicit DENY always wins; no matching permission means DENY.
Company-only scopes.Assignments bind a company; no org-unit paths; own-row rule covers personal data.
No executable expressions.Scopes and policies use controlled operators; custom expressions are rejected by CHECK.
Maker-checker on privilege.Granter never approves; privileged roles wait for a second approver.
SoD (Segregation of Duties) pre-commit and after.Dry-run blocks conflicting grants; reports catch drift after re-orgs.
Delegations always expire.Mandatory window plus sweeper; revocation invalidates delegatee decision keys at once.
Versions invalidate, ancestors included.Role, grant, policy, scope, group, and delegation changes delete affected keys and bump the policy version.
Tenant and company fenced.Every row carries the path; cross-tenant access returns zero rows.
