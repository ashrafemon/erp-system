08 · Saga — Company-Configurable Orchestration

Role: long-running cross-aggregate processes on an ERP-standard default that every company reshapes with its own features, settings and overrides. Any company, any combination — validated before it runs, snapshotted per instance.

Contents · Ports · Tables · Definitions · Format · Flow · Sequence · Patterns · Examples · Layout · When not · Config · Rules

Public ports

The saga owns no billing, plans or subscriptions — only feature keys + settings arriving through ports owned outside it. Business modules expose actions; the saga calls them, never repositories.

methods
FeatureGate.enabled(companyId) → ReadonlySetOpaque capability keys (procurement, valuation, finance …) — owned outside the saga, never interpreted inside.
CompanySettingsReader.get(companyId) → settingsgrnSources, costingMethod, accrual flags — read at plan build, snapshotted, never re-read mid-flight.
SagaAction.do(ctx) → ok | retry | failOne command on one aggregate via its application service; ctx carries companyId, instanceId, stepId, idempotencyKey (= step row id).
SagaAction.undo(ctx + doOutput) → ok | retry | failBusiness reversal (reversal document, never delete); idempotent, retried until ok; receives original input + output.
SAGA_ACTION multi-provider tokenEach module registers its own actions; SagaModule imports nothing from business modules.

Definition format

Linear steps, three small expressions, safe evaluator (JEXL/CEL — never eval). Variables: event, saga, company.settings, steps.<id>.status/output. Templates use {{ }}.

field → meaning
saga: key, version, requiresidentity + feature keys the saga needs to exist at all
start: on, when?, key, contexttrigger event, optional event filter, instance-key template, values copied into the saga
cancelOn[]events that cancel a live instance and compensate (e.g. po.cancelled → match PO key)
step: id, policyrequired (cannot be switched off) / standard (on, can be switched off) / optional (off, can be switched on)
step: do, undo, input?action names + optional input built from earlier outputs; every do needs undo or pivot
step: waitFor, match, when?event type, key template equal to the instance key, per-event filter
step: requires, if?feature keys (bypass if missing), condition when reached (bypass if false)
step: timeout, onTimeoutwaits only: skip or compensate
step: retry, pivotmax attempts for technical failures; pivot = point of no return
onComplete.emitsaga lifecycle event on finish (e.g. inventory.grn.posted)

Flow — plan, route, run

sequence
1Publish: platform BASE definition (ERP-standard steps) or company OVERRIDE (enabled/when/timeout/retry only — never do/undo/requires, never required-off). Unknown step, bad expression or failed checks reject the publish.
2Plan build per company: drop steps whose requires are missing (bypass by feature), drop override-disabled (error if required), drop non-enabled optional; validate ids, expressions, actions, undo-or-pivot; empty plan → no instance is ever created.
3Router per event, 5 checks in order: requires+policy (exists for this company?) → override (allowed?) → if (relevant now?) → when (this event?) → match (this instance?). Bypass means continue, never wait — a saga never waits for an event the company cannot produce.
4Start: inbox tryInsert (company, saga, eventId) — duplicate skipped; instance + plan snapshot + cursor 0 under one live key; advance runs at once.
5Advance: if false → SKIPPED; do → PENDING row, stop for the worker; wait → consume oldest BUFFERED match or create WAIT row (run_at = timeout), status WAITING, stop.
6Worker claims PENDING rows (SKIP LOCKED + 60s lease, small batch, per-company fairness cap) → runs the action with idempotencyKey = step row id → ok stores output, retry backs off, fail compensates.
7Wait expiry, exhausted retries, business fail or cancelOn event → COMPENSATING with reason → UNDO rows in reverse completion order (worker retries until ok) → COMPENSATED + saga event, or FAILED_MANUAL + alert. Running actions are never killed (cancel_requested_at waits for them).
8Early events BUFFER by match and are consumed when their step arrives; causationId ignores the saga's own output (loop guard).
9Config changes (features, settings, overrides) affect new instances only — running ones finish on their snapshot; revoked features keep actions callable so undo still works; invalid config flags CONFIG_INVALID (no new instances) + alert.

Config — robustness + efficiency

engine
WORKER_LEASE_S + CLAIM_BATCH60s lease, SKIP LOCKED small batch — workers never block each other
WAIT_AS_ROWStimeouts are PENDING rows (run_at = instant) — no separate scheduler
WAKEUPSnotify on new rows (LISTEN/NOTIFY or BullMQ) + slow poll fallback
FAIRNESS_CAPmax rows claimed per company per batch — no starvation
RETENTIONpartition saga_steps by month; archive finished instances; purge inbox after the redelivery window (days, batched)
OUTBOX_RELAYbatches ordered by created_at, partition_key for per-aggregate order

Rules

rules
Aggregates never know about sagasThey emit domain facts (grn.created, bill.posted) into the outbox; one step = one command on one aggregate via its application service.
Saga holds process state, aggregate holds business stateNever copy Posted into the saga; compensation calls a domain method (grn.markPostingFailed); undo creates reversal records, never deletes.
Business fail vs technical retryfail reason → compensate at once; retry → backoff to max_attempts; exhausted undo → FAILED_MANUAL + alert.
Pivot = point of no returnAfter a pivot step (e.g. executePayment) the saga only moves forward.
Empty plan means no instanceNo features, saga disabled, or every step bypassed → router stops; the event still exists for plain handlers.
Snapshots are immutableRunning instances finish on their plan; new instances get new plans; revoked features keep actions callable so undo works.
Company in every keyInstances, steps, inbox rows, cache entries, queue claims — every query filters by company_id.
Idempotency first, inbox secondMake handlers idempotent; add inbox rows only when they cannot be; insert inbox in the same tx as the work.
Loop guardIgnore events whose causationId is the saga's own step output.
Closed periods + alertsReversals post in the open period; alert on FAILED_MANUAL, CONFIG_INVALID, overdue WAITING, growing PENDING.
No business importsPlatform never imports business modules; actions arrive via SAGA_ACTION providers.
