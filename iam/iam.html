ERP Auth Service — Tenancy, Identity, Authentication

Role: central entry service for the ERP. Tenants isolate, companies are the workable workspace: membership scopes, and every grant targets a company. Proves identity (Authentication), holds the session, resolves the entitled context. The decision itself lives in the separate Authorization service. One login, every center.

Public ports

ERP guards inject IamEntitlementPort to resolve context and IamSessionPort to verify sessions. Decisions come from the Authorization service. Frontend ids are never trusted.

methods
resolveContext({ user, tenant, company, center }) → entitled contextHinge active plus window, tenant active; company mandatory in scopes; center active and entitled.
getScopes({ membership }) → companies with accessReads mandatory company scopes. No company grant means no workspace.
verifySession({ sessionId }) → identity | expiredRedis lookup with version check, O(1) (constant-time) revoke.
// backend guard: resolve context, then ask the Authorization service
const context = await this.iamEntitlement.resolveContext({ user: userId, tenant: tenantId, company: companyId, center: 'ERP' });
const decision = await this.authorization.check({ ...context, resource: 'purchase-order', action: 'approve' });
if (decision.status !== 'ALLOW') throw new ForbiddenException();
return this.purchaseOrders.approve(id, decision.scopeFilter);

Flow — complete auth plus authorization

gates in order, default DENY (deny by default)
1Center gate — Resolve center from Host. Unknown or inactive center ends DENY (deny by default).
2Session gate — Redis GET session by id. Missing, expired, revoked, or inactive user ends 401. Success may trigger central login (password, MFA (Multi-Factor Authentication), OTP (One-Time Password), passkey, SSO (Single Sign-On)) with attempts logged and rate-limited.
3Membership gate — Membership of user times tenant must be active and inside its window, tenant active. Else DENY (deny by default).
4Workspace gate — membership_scopes must include the chosen company; company is mandatory. No company grant means no workspace, request denies. Company ids are checked server-side, never trusted from the client.
5Center active gate — Requested center must be active. Else 403.
6Decision call — Forward the entitled context to the Authorization service. It returns ALLOW plus company scope filter plus obligations, or DENY.
7Domain gate — ERP module validates its own invariants (draft status, thresholds). Failures answer 422, not 403.
8Commit plus audit — Append security_events (plus sensitive_access_log on reads and exports) and the outbox row in the same transaction.
9Async fan-out — Outbox relay deletes authz keys and revokes sessions where needed.

Cache keys

Cache never holds source of truth. Every mutation emits outbox in the same transaction, then invalidates. Auth decisions fail closed on miss.

keys
session:{sessionId}session row + user.status snapshot. TTL session lifetime (sliding). Invalidated by logout/revoke; suspend bumps session_version. Redis; O(1) revoke; regeneration on privilege change
user:sessions:{userId}SET of session ids. TTL session lifetime. Invalidated by logout-all (DEL set). index for revoke-all
session_version:{userId}counter. TTL long-lived. Invalidated by logout-all/suspend/password-reset. in-flight short contexts checked or expire naturally
membership:{membershipId}membership + scopes snapshot. TTL short (e.g. 60-300s). Invalidated by MembershipCreated/Revoked/Expired. never trust stale beyond TTL
tenant:{slug}tenant id+status. TTL 10 min. Invalidated by tenant status change. fail-closed while provisioning/offboarding
rate:login:{identity} etccounters. TTL window TTL. Invalidated by natural expiry. auth_transactions + attempts back it
challenge:{id}challenge hash. TTL minutes. Invalidated by consume/expire. code_hash only

4.0 IdentityVerifiedTrigger: verified_at set. Effect: promote primary; notify. Via outbox
5.0 SessionCreatedTrigger: sessions+refresh commit. Effect: cache session:{id}. Via outbox
6.0 SessionRevoked / AllSessionsRevokedTrigger: logout/suspend/reset. Effect: DEL session / bump version. Via outbox
7.0 MembershipCreated/Revoked/ExpiredTrigger: membership lifecycle. Effect: invalidate membership:* + authz:decision:*. Via outbox (+hourly sweep for expiry)
14.0 ApiKeyRevoked/RotatedTrigger: api_keys status flip. Effect: immediate deny for machine. Via outbox
15.0 AnomalousApiUsageTrigger: spike/bulk/off-hours. Effect: limiter trip + alert. Via outbox

Rules — ERP identity standard

rules
Tenant isolates, company works.Tenant is the isolation boundary and onboarding container. Company is the workspace; every grant targets a company; users switch companies on one session.
Membership needs a company.The hinge joins user to tenant, but working rights come from mandatory company scopes. No company row means no workspace and every request denies.
No org units.Flat company list per tenant. Scopes are company-only; no hierarchy paths to maintain or bypass.
Never trust frontend ids.Tenant, company, and role ids re-resolve server-side via membership scopes; forged ids answer 403 plus audit.
Tenant path on every owned row.Cross-tenant access returns zero rows; NULL-tenant uniqueness closed with NULLS NOT DISTINCT.
Secrets hashed only.Argon2id or bcrypt, history N, min length 12; OTP (One-Time Password) and API values as hashes; IdP secrets as manager pointers.
Sessions server-side.Redis plus Secure, HttpOnly, SameSite cookies; rotation on privilege change; one call kills user, sessions, and keys.
Cache never decides.Every mutation emits outbox in the same transaction, then invalidates; auth decisions fail closed on miss.
Audit is append-only.Hash-chained security events, no UPDATE or DELETE grants; sensitive reads logged with justification; no secrets in payloads.
Abuse contained.Login, OTP (One-Time Password), and tenant rate limits plus anomaly trips; recovery completion kills sessions; SSO (Single Sign-On) never auto-links on email match alone.
Reliability reused.Outbox, Inbox, Cache, Lock, and Idempotency come from the platform; Auth owns only its rows and checkpoints.
