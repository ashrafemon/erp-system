03 · Distributed Lock — Redis-Only Mutual Exclusion

Role: one-winner-now ownership of a resource across replicas (scheduler ticks, numbering sequences, batch chunks). Fail-closed. Lease-based, never a cache key.

Contents · Ports · Flow · Sequence · Layout · Config · Rules

Public port

Inject DistributedLockPort to own a resource across replicas. You hold a ticket, never a boolean. It never waits.

methods
acquire({ scope, resource }) → ACQUIRED + ticket, or BUSYOne winner. BUSY carries retryAfterMs. You decide: 409, retry, or queue.
renew({ ticket }) → RENEWED, or LOSTLOST means someone else owns it now. Stop work immediately.
release({ ticket }) → voidGives it back. Always in a finally block.
key shape lock:{tenant}:{company}:{scope}:{resource}Same id in two companies locks independently. Redis errors fail closed.
const lock = await this.distributedLock.acquire({ tenantId, companyId, scope: 'numbering.invoice', resource: sequenceId });
if (lock.status === 'BUSY') throw new ConflictException();
try {
  return await this.nextNumber(sequenceId);
} finally {
  await this.distributedLock.release({ ticket: lock.ticket });
}

Flow

sequence
1const lock = await distributedLock.acquire({ scope: 'numbering.invoice', resource: sequenceId });
2if (lock.status === 'BUSY') throw ConflictException, otherwise run the critical section and renew every third of the lease on long jobs.
3distributedLock.release with lock.ticket always runs in a finally block.
4Never wait/block inside the service — caller decides retry/409/queue. Redis error, throw (fail-closed), never assume ownership.

Rules

rules
Lock ≠ cache, ≠ idempotency. Short lease + periodic renew; release in finally.
Scope examples: inventory.stock · numbering.invoice · scheduler.job · batch.operation.
Redis keyspace lock:* owned solely by this service.
Uses the infra Redis client directly, never CachePort.One shared client, separate abstractions. The lock reuses the same single Redis connection the Cache adapter uses (one client, one config, no private connection), but never calls CachePort: lock is fail-closed ownership (SET NX PX plus Lua owner check), cache is fail-open disposable reads. Routing the lock through the cache would inherit miss-on-error and break mutual exclusion.
