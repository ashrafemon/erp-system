08 · Saga — Configurable Versioned Orchestration

Role: cross-aggregate long processes on versioned definitions — the platform ships templates, companies publish their own versions. Each version stores one runnable definition graph; the engine runs exactly what is stored.

Contents · Ports · Tables · Flow · Definitions · Examples · Flow · Sequence · Layout · When not · Config · Rules

Public ports

Three surfaces. Teams publish definition versions (template or company). The engine runs the stored definition only. Event/action contracts live in code registries next to the handlers.

methods
PublishDefinitionVersion(definition) → VALIDATED → ACTIVEChecks (required triggers, param values, limits, final-state reachability); same config_hash reuses the version; ACTIVE rows are immutable — changes publish a new version.
CompanyVersion: RESOLVED or CUSTOM full graphRESOLVED: company-resolved runnable graph; CUSTOM: company-authored runnable graph. No extends, no recompile — what is stored is what runs.
Router routes:{companyId}:{eventType}Cache built from active definitions; each entry holds sagaKey, version, triggerKey, role, condition, correlate.
Engine intake → transitionInbox insert + state change + history row + outbox row in ONE DB transaction; actions run later from the queue with retries.
EVENT_REGISTRY / ACTION_REGISTRY (code)Event name + schema (+ discriminator); action handler + compensation + maxAttempts + timeoutSec. Contract tests check payloads.

Flow

sequence
1Platform team publishes the TEMPLATE version (schema saga/v1, e.g. procure_to_pay with params, triggers, states).
2Company publishes its version: the full runnable graph (states, triggers, params inlined) — TEMPLATE for platform, RESOLVED/CUSTOM for companies.
3Publish checks: every required trigger is active; param values are in the template values; steps/retries/conditions are within limits; every state reaches a final state — violations reject the save and the previous version stays.
4Identical config_hash reuses the version (no duplicate publishes); template upgrades publish new full versions per company — there is no auto-recompile.
5ACTIVE version set on the definition + saga.definition.published emitted — the row is immutable from here.
6Router builds routes:{company}:{event} from the active definitions (sagaKey, version, triggerKey, role, condition, correlate); a missing entry rebuilds from the versions.
7Event arrives → inbox insert UNIQUE(company, consumer_key, event_id) — duplicate delivery collapses on the key.
8START role + correlate key (e.g. PO:po_55) → create the instance pinned to the version; ADVANCE role → the correlated instance must exist, else DEFERRED.
9Transition commits ONE tx: inbox row + instance state + history (sequence_no) + outbox row (stable event_id).
10Actions run from the queue keyed by execution_key; bounded retries (max_attempts, next_retry_at); the worker holds the run until started_at + timeout.
11Failure → compensation actions — new cancel/release ops, never rollbacks — terminal FAILED/CANCELLED/TIMED_OUT.
12Event before the right state → DEFERRED, re-driven when the state is entered, DEAD_LETTER after a TTL; one event × N sagas = one inbox row per consumer_key.
13New versions only affect new instances — running instances finish on their pinned version; history of every config change lives in the old version rows.

Rules

rules
Sheet columns are the contractTables carry exactly the sheet columns; behaviour (uniques, atomicity, defer, retry) follows the reference below.
Pinned versionsInstances stay on definition_version_id; new versions only affect new instances; config history lives in old rows.
Atomic transitionInbox + state + history + outbox commit in one tx; actions run later from the queue — never inline.
Immutable ACTIVECompany changes publish a new version; violations reject the save and the previous version stays.
Isolationtenant_id/company_id on all 7 tables; NULL company only on PLATFORM templates; cache key carries company + version.
One running saga per documentEnforced on (company_id, saga_key, correlation_id) while status is running — finished rows never block.
Dedupe by keyUNIQUE(company_id, consumer_key, event_id) on the inbox; stable event_id on the outbox.
No business importsPlatform never imports business modules; handlers inject the ports they need.
