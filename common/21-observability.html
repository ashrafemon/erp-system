21 · Observability — Logs/Metrics/Errors

Role: structural seams behind ports. Console logger, Prometheus metrics (erp_ prefix), Sentry (self-disables without DSN).

Contents · Ports · Flow · Sequence · Layout · Config · Rules

Public ports

Inject ports — never prom-client / sentry SDKs directly.

methods
LoggerPort.debug/info/warn/error/fatal(msg, fields?)ConsoleLoggerAdapter: console + [LEVEL] msg json; request logging via LoggingInterceptor, never bodies.
MetricsPort.registerCounter/Histogram/Gauge + increment/observe/set + getMetrics()PrometheusMetricsAdapter: own Registry, app=erp-api, prefix erp_, collectDefaultMetrics; unregistered increment = no-op.
ErrorTrackingPort.captureException/Message(err, {requestId,correlationId,tenantId,...})SentryErrorTrackingAdapter withScope; self-disables without DSN; zero consumers today — wire global filter to use.
GET /api/v1/metrics (@SkipTenancy())MetricsController exposition.

Flow

sequence
1Inject port → adapter. Logger: direct console structured JSON.
2Metrics: registerX then increment/observe/set; controller renders exposition text.
3Sentry: withScope apply ctx tags → captureException/Message; Sentry.init in bootstrap.
4Pass CLS fields explicitly — no auto-attach.
